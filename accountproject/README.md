# ЛабКонтроль — CRM для лабораторных организаций

Веб-приложение для автоматизации процесса от заявки клиента до финального заключения лабораторной организации.

The app is a React frontend (this directory) backed by a real API + database
in `server/` (Express + SQLite). See `server/README.md` for backend details.

---

## Быстрый старт

Two processes: the API server and the React dev server.

```bash
# Terminal 1 — backend (API + SQLite database)
cd server
npm install
npm start        # http://localhost:4001, seeds the DB on first run

# Terminal 2 — frontend
npm install
npm start         # http://localhost:3000, proxies /api to the backend
```

For a single-process deployment, build the frontend and let the backend
serve it:

```bash
npm run build
cd server && npm start   # now serves both the API and the built app on :4001
```

## Тестирование на своём ПК (Windows)

Пошаговая инструкция, как поднять и проверить приложение локально.

### 1. Предустановки

- **Node.js** 18+ (проверьте: `node -v`, `npm -v`). Если нет — поставьте с
  [nodejs.org](https://nodejs.org/).
- **Git** для Windows (для `git clone`/`git pull`), либо просто скачанный zip
  репозитория.
- Любой современный браузер.

Команды ниже даны для **PowerShell** (или обычного `cmd`) и для **Git Bash** —
они почти не отличаются, разница отмечена отдельно.

### 2. Получить код нужной ветки

Разработка идёт по схеме: `local` — черновые правки без бэкенда,
`feat1` — полная версия с реальным backend'ом (Express + SQLite). Для
тестирования "боевой" версии с базой данных нужна ветка **`feat1`**:

```powershell
git clone <URL репозитория> account
cd account\accountproject
git checkout feat1
git pull origin feat1
```

Если репозиторий уже склонирован — просто:

```powershell
cd account\accountproject
git checkout feat1
git pull origin feat1
```

> ⚠️ Если раньше вы переключались на ветку `local` (без бэкенда) и в папке
> `accountproject` видите лишнюю папку `server`, это нормально — `git checkout`
> не трогает файлы, которые Git не отслеживает (`node_modules`, `data`,
> `uploads`). Ничего удалять не нужно: на `feat1` эта папка `server` как раз
> и есть бэкенд, он должен быть на месте.

### 3. Установить зависимости и запустить оба процесса

Нужны **два отдельных терминала/окна** — один для backend, один для frontend.
Оставляйте оба открытыми, пока тестируете.

**Терминал 1 — backend (API + база данных):**

```powershell
cd account\accountproject\server
npm install
npm start
```

Должно появиться сообщение о запуске на `http://localhost:4001`. При первом
запуске автоматически создаётся файл базы данных `server/data/app.sqlite` и
заполняется демо-данными (аккаунты, заявки, туры) — это нормально, так и
задумано.

**Терминал 2 — frontend:**

```powershell
cd account\accountproject
npm install
npm start
```

Браузер должен сам открыться на `http://localhost:3000` (если нет — откройте
вручную). Фронтенд проксирует запросы `/api/*` на backend, поэтому оба
процесса обязательны — без запущенного backend'а вы увидите ошибки вида
`ECONNREFUSED` в консоли фронтенда.

> Фикс краша `webpack-dev-server` в контейнерных/песочных окружениях уже
> зашит в `npm start` (флаг `DANGEROUSLY_DISABLE_HOST_CHECK`), на обычном
> Windows-ПК он никак не влияет и ничего ломать не должен.

### 4. Войти и проверить

Откройте `http://localhost:3000/login` и войдите одним из демо-аккаунтов:

| Роль            | Email                | Пароль      |
|-----------------|-----------------------|-------------|
| Администратор   | admin@csee.kz         | Admin123!   |
| Администратор 2 | admin2@csee.kz        | Admin456!   |
| Заведующий 1    | manager1@csee.kz      | Mgr123!     |
| Заведующий 2    | manager2@csee.kz      | Mgr456!     |
| Клиент 1        | client1@lab.kz        | Client123!  |
| Клиент 2        | client2@lab.kz        | Client456!  |
| Клиент 3        | client3@lab.kz        | Client789!  |

Что стоит проверить в первую очередь (последние доработки):

- **Тур скрыт от клиента.** Зайдите как `client1@lab.kz` — заявка `ЗАЯ-2024-001`
  должна показывать статус «Организация тура ППК» без упоминания слова
  «тур»/номера тура/ссылки на страницу тура. Затем зайдите как `admin@csee.kz`
  или `manager1@csee.kz` — там тур виден полностью, с номером и деталями.
- **Тосты и анимации.** Как admin откройте любую заявку в статусе «ожидает
  принятия», нажмите «Принять» — должен появиться всплывающий тост об успехе
  и на секунду подсветиться (flash) бейдж статуса. На детальной странице
  заявки активный шаг в трекере статусов должен слегка пульсировать
  (idle-анимация), а непрочитанные уведомления в сайдбаре — тоже пульсировать
  красным.
- **Загрузка/скачивание файлов.** Как admin прикрепите драфт договора
  (реальный файл) на заявке — ссылка на файл должна вести на
  `http://localhost:4001/uploads/...` и открываться/скачиваться. Затем
  зайдите тем же клиентом, за которого создана заявка — файл, загруженный
  admin'ом, должен открываться и у него, и наоборот (клиент загружает
  подписанный договор — admin должен суметь его скачать).

### 5. Сбросить базу данных между тестами (по желанию)

Если хотите начать с чистого состояния (например, после того как надобавляли
тестовых заявок), остановите backend (`Ctrl+C` в терминале 1) и удалите файл
базы:

```powershell
# PowerShell
Remove-Item account\accountproject\server\data\app.sqlite*

# cmd
del account\accountproject\server\data\app.sqlite*

# Git Bash
rm accountproject/server/data/app.sqlite*
```

При следующем `npm start` база будет создана и заполнена демо-данными заново.

## Роли и права доступа

### Администратор (`admin`)
- Полный доступ ко всем заявкам
- Подписание / отклонение заявок
- Назначение лаборантов на заявки
- Отправка протоколов клиентам
- Создание итоговых заключений
- Управление пользователями
- Доступ к архиву / журналу

### Лаборант (`manager`)
- Видит назначенные ему заявки + все ожидающие
- Создание протоколов испытаний
- Уведомление администраторов
- Доступ к своим протоколам

### Клиент (`client`)
- Регистрация с email-верификацией
- Подача заявок по программам
- Просмотр только своих заявок
- Получение и подтверждение протоколов
- Получение и подтверждение заключений

## Архитектура

Раньше `data/store.js` был in-memory singleton'ом, хранившим все данные и бизнес-логику
прямо в памяти браузера — при обновлении страницы всё терялось. Теперь:

- **`server/`** — реальный backend: Express + SQLite (через `better-sqlite3`).
  Вся бизнес-логика (переходы статусов, авто-создание туров, уведомления) живёт
  в `server/src/repo.js` и выполняется на сервере против базы данных.
  Пароли хранятся как bcrypt-хэши, сессии — через JWT.
- **`src/api/client.js`** — тонкая обёртка над `fetch()` для вызова API.
- **`src/context/StoreContext.js`** — клиентский кэш: читает данные с бэкенда,
  а все мутации (`acceptApplication`, `startTour`, ...) идут через реальные
  API-запросы и обновляют кэш из ответа сервера.
- **`data/store.js`** — теперь содержит только презентационные константы
  (подписи и цвета статусов), не данные.

Подробности backend API — в `server/README.md`.

## Уведомления

Типы уведомлений:

| Тип | Получатель | Триггер |
|-----|-----------|---------|
| `application_submitted` | Администраторы | Клиент подал заявку |
| `status_changed` | Клиент | Статус заявки изменён |
| `manager_assigned` | Лаборант | Назначен на заявку |
| `protocol_ready` | Администраторы | Лаборант создал протокол |
| `protocol_sent` | Клиент | Протокол отправлен |
| `protocol_delivered` | Администраторы | Клиент подтвердил протокол |
| `result_sent` | Клиент | Заключение готово |

## Разработка и расширение

### Добавление новой программы
1. В `src/data/store.js` добавьте объект в массив `PROGRAMS`
2. Добавьте описание полей формы в объект `PROGRAM_FORMS`

### Добавление новой роли
1. Добавьте навигацию в `Layout.jsx` (объект `ROLE_NAV`)
2. Добавьте проверку прав в `ProtectedRoute` в `App.jsx`
3. Создайте соответствующие страницы

### Кастомизация темы
Все цвета — в CSS-переменных в `src/index.css`:
```css
:root {
  --accent: #4f8ef7;    /* Основной акцент */
  --green: #3cc98a;     /* Успех */
  --yellow: #f5c542;    /* Предупреждение */
  --red: #f75959;       /* Ошибка */
  --purple: #a47fff;    /* Протоколы / лаборант */
}
```
